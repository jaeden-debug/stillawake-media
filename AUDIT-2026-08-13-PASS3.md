## 14. llms.txt GENERATOR — PRODUCT SPECIFICATION

### Competitive reality (live SERP)
| Tool | What it does | Weakness |
|---|---|---|
| Firecrawl (GitHub) | Crawls, dumps `llms.txt` + `llms-full.txt` | Developer-only; no guidance |
| SiteSpeakAI | URL in, file out, ~30s | Pure dump; no reasoning |
| AdNabu | Platform-focused (Shopify/WP) | Template-driven |
| WordLift | Crawl + spec-compliant output | Gated behind their platform |
| LLMrefs | Crawl + AI page descriptions | Closest competitor |
| llmstxtgenerate.com | EMD, basic | Thin |

**The gap:** every one of them **crawls and summarises**. None of them **reasons about the entity**. They answer "what pages exist"; they never answer *"can an answer engine tell who you are, what you sell, where you operate, and what it costs?"* — which is the actual question `llms.txt` exists to solve.

### The differentiator
**Ship a scored diagnostic, not a file dump.** Output the file *and* a report of what is missing:

> ⚠️ No pricing found on any page — answer engines cannot quote your cost
> ⚠️ No organization entity detected — no `Organization` schema with a stable `@id`
> ⚠️ Service pages found, but none state where you operate
> ✅ Founder identified and linked

That is a **free audit that produces a lead**, disguised as a utility. It is also honest: every warning is a real deficiency the visitor can fix.

### MVP
- Domain input → fetch `robots.txt`, `sitemap.xml`, homepage
- Detect: organization name, founder, services, pricing signals, contact, existing JSON-LD, existing `llms.txt`, languages
- Rank pages by sitemap priority + internal link count
- Generate spec-compliant `llms.txt` with sectioned summaries
- **Readiness score + missing-signal warnings** ← the differentiator
- Editable preview · copy · download
- Explain each recommendation
- Hard limits: 100 pages, 30s, public URLs only

### V2
`llms-full.txt` · multilingual (your bilingual work is directly reusable) · re-check + diff over time · schema gap analysis feeding a second tool · optional email report (**the lead capture — must be optional; a gate kills the linking that justifies the build**) · CMS-specific guidance

### Abuse controls
Public HTTP(S) only · **block private/loopback/link-local ranges (SSRF)** · robots.txt respected · per-IP rate limit · 30s and 5MB caps · redirect cap · no auth headers ever · no storage of crawled content beyond the session

### SEO landing page
`/tools/llms-txt-generator` — targets `llms txt generator` (480/mo, MODERATE), `llms.txt example`, `how to create llms.txt`, `what is llms.txt`, `llms.txt for shopify`. Tool above the fold, explainer below.

### Architecture
Next.js route handler on Vercel · server-side fetch/parse · no DB for MVP (stateless) · streaming progress · Cheerio + XML parse, no headless browser (cost, and the SSRF surface is smaller)

### Complexity
**MVP 3–5 focused days.** V2 another 3–4. Maintenance low — the spec is small and stable, unlike schema.org.

### Lead path
Tool → readiness warnings → *"We fix these"* → `/answer-engine-optimization` → `stillawake.studio/start`
